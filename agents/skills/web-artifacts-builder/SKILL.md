# Web Artifacts Builder

Use this skill to build a frontend project and package it as one HTML file:

1. Initialize a project with `scripts/init-artifact.sh`.
2. Develop the artifact in the generated React + TypeScript project.
3. Bundle the project with `scripts/bundle-artifact.sh`.
4. Display or share `bundle.html`.

## Stack

The generated project uses the latest versions of:

- React and TypeScript through Vite.
- `@base-ui/react` for accessible, headless UI primitives.
- `cmdk` for command menu behavior when needed.
- CSS Modules and plain CSS; no utility-class build step or generated component archive.
- Vite's Rolldown build path with `vite-plugin-singlefile` for the final HTML artifact.
- Fine-grained Shiki highlighting for exactly `hbs`, `ts`, `tsx`, `js`, `jsx`, `html`, `gts`, `gjs`, `md`, `mdx`, `css`, `json`, and `jsonc`.
- Catppuccin Latte and Mocha tokens selected from the operating system's light or dark preference.
- Atkinson Hyperlegible Next for prose, Fira Code for code, and Symbols Nerd Font for icon glyph support.

The initializer assumes Node.js and pnpm are already installed. It reports an error and exits when either prerequisite is missing; it never installs tools globally. All package requests use `@latest`.

The bundled `resources/style-guide.md` is the source reference for the Catppuccin resource. The generated global stylesheet contains the runtime theme tokens so the artifact does not need to read a file at runtime.

## Design and style guidelines

Build interfaces that feel intentional and specific to their task. Avoid generic centered layouts, purple gradients, excessive rounded cards, and default system typography. Prefer a clear visual hierarchy, responsive constraints, accessible focus states, and a small number of purposeful interactions.

Use Base UI primitives directly and style them with colocated CSS Modules. Keep global CSS for tokens, typography, resets, and shared browser behavior. Do not add a theme toggle: the generated project follows `prefers-color-scheme` automatically.

For code surfaces, use the included highlighter component and keep the language set within the supported list. Use contextual ligatures with Fira Code and put Symbols Nerd Font after it in the code font stack so Nerd Font glyphs remain available.

## Quick start

### Initialize a project

Run the initializer from the skill directory:

```bash
bash scripts/init-artifact.sh <project-name>
cd <project-name>
```

The generated project includes a working Base UI button, CSS Modules, Catppuccin system themes, font setup, the narrow Shiki highlighter, and a Vite configuration for single-file output.

### Develop the artifact

Edit the generated `src` files. Use normal React composition and Base UI imports such as:

```tsx
import { Button } from "@base-ui/react/button";

export function SaveButton() {
  return <Button>Save</Button>;
}
```

For more complex primitives, assemble the parts from their package entrypoint. For example, dialogs use `Dialog.Root`, `Dialog.Trigger`, `Dialog.Portal`, and `Dialog.Popup` from `@base-ui/react/dialog`.

### Bundle the artifact

Run this from the generated project root:

```bash
bash ../scripts/bundle-artifact.sh
```

The script runs `pnpm exec vite build`, expects Vite to emit `dist/index.html`, copies that file to `bundle.html`, and removes the temporary `dist` directory. It does not install packages or mutate the project's dependencies.

The final summary includes a clickable, URL-encoded `file://` link for opening `bundle.html` directly in a browser.

The result is one HTML file with the generated JavaScript and CSS inlined. External web font URLs remain network resources, so embed local font assets in the project when an offline font guarantee is required.

### Optional visualization

Testing and visualization are optional. Use a browser tool when visual inspection is useful or requested; no test suite is generated by this skill.
